# Фронтенд: материал для дизайна

Документ самодостаточен: его можно отдать дизайнеру или инструменту для макетов вместе с папкой [design/references](../design/references/), остальные файлы не нужны. Здесь описано, какие экраны нужны, какие данные на них есть и какие состояния надо учесть. Внешний вид задают референсы, см. раздел 3.

## 1. Продукт коротко

Planny — закрытый планировщик для одной семьи. У каждого человека свой календарь. Совместная работа идёт через совместные события, общие доски и назначение задач. Регистрации нет, аккаунты создаёт администратор сервера. Интерфейс на русском, один адаптивный сайт для компьютера и телефона.

## 2. Правила, которые влияют на интерфейс

- **Приглашений нет.** Человек добавляется в событие сразу. Нет статусов «принял» и «отклонил», нет входящих, нет полупрозрачных событий.
- **Участники события равноправны.** Любой участник может всё: менять поля, добавлять и убирать людей, удалить событие у всех. Создатель ничем не выделяется.
- **Чужая занятость видна всем, детали нет.** Другой человек видит только «занят с 15:00 до 16:00». Нет разрешений и настроек доступа.
- **Категория личная.** Одно и то же совместное событие может быть зелёным у одного участника и синим у другого. Категория не связана с доступом.
- **Напоминание личное.** У каждого участника своё.
- **Задача не занимает время.** Она показывается в календаре на дату дедлайна и не считается занятостью.
- **Всё живёт в доске.** Список, Kanban и календарь — виды одной доски. Личная доска есть у каждого.
- **Колонка определяет статус.** Перенос в завершающую колонку отмечает задачу выполненной, а отметка чекбокса переносит её туда.
- **Уведомления только внутри сайта.** Они копятся и видны при следующем входе. Push и PWA нет.
- **Серия меняется только целиком.** Изменить или удалить один повтор в первой версии нельзя.

## 3. Визуальное направление

Тёмная тема, сдержанные сине-зелёные акценты, современный минимализм. Ориентиры:

- Почти чёрный фон с сине-зелёным оттенком, полупрозрачные панели чуть светлее, тонкие границы.
- Мягко скруглённые панели и карточки.
- Один зелёный акцент: активный пункт навигации, выбранный сегмент, главная кнопка. На главных кнопках он яркий, с лёгким градиентом.
- События окрашены цветом категории: заливка приглушённая, текст читаемый. В списках вместо заливки цветная полоса слева.
- На экранах входа и смены пароля фон с тёмным силуэтом гор и бирюзовым свечением, по центру панель с логотипом.
- Заметные состояния фокуса и нажатия.

Нужны такие группы токенов. Значения снимаются с референсов на этапе 1 и живут в коде:

| Группа | Что должно быть |
|---|---|
| Поверхности | Фон страницы, панель, карточка, приподнятый слой для окон |
| Текст | Основной, второстепенный, приглушённый, на акценте |
| Акцент | Основной, при наведении, приглушённая заливка |
| Состояния | Успех, предупреждение, ошибка, информация |
| Границы | Обычная, фокус |
| Категории и метки | Палитра из 8 цветов, отличимых друг от друга на тёмном фоне. Ключи: `violet`, `blue`, `teal`, `green`, `yellow`, `orange`, `red`, `pink` |
| Приоритеты | P1, P2, P3, P4 |

Светлая тема в MVP не нужна, но значения лучше сразу задавать токенами.

### Референсы

В папке [design/references](../design/references/) лежат изображения экранов, сгенерированные нейросетью. Это ориентир по визуалу: цвет, типографика, плотность, форма панелей и карточек. Спецификацией они не являются, поэтому дословно повторять их не нужно. Какому экрану соответствует какой файл, показано в разделе 5.

Стиль референсов общий для всего приложения. Отдельные макеты всех экранов не нужны: экран без референса строится в том же стиле из тех же компонентов, а его основа указана в разделе 5. Мобильные версии опираются на [мобильный календарь](../design/references/mobile-calendar-month.png).

Если референс расходится с этим документом, верен документ. Известные расхождения:

| На референсах | Как должно быть |
|---|---|
| Белый текст на ярко-зелёных кнопках | Тёмный текст: у белого на этом зелёном контраст около 2:1 |
| Приоритеты «Высокий», «Средний», «Низкий» | Четыре приоритета, см. раздел 8 |
| Фотографии в аватарах | Кружок с инициалом и цветом пользователя, загрузки фото нет |
| Свои иконки у событий: гантель, шапочка, корзина | Поля иконки у события нет, только значки «совместное» и «повтор» |
| «Чт, 6 ноября» и неделя «3–9 ноября» | Ошибка генерации: 6 ноября 2026 года — пятница |
| Нет строки «Весь день» на виде недели | Строка нужна и на неделе, и на дне |
| Событие вложено в другое на виде дня | Пересекающиеся события стоят рядом |
| Одна дата в форме события | Начало и конец могут приходиться на разные дни |
| Нет занятости участников в форме события | Она нужна, см. раздел 6.5. Дорожка справа хорошо для неё подходит |
| Маркеры растягивания на дорожке времени | Перетаскивания в форме нет, время задаётся полями |
| Категории у задач: подпись в строке и фильтр | Категории есть только у событий, в строке задачи показывается доска |
| Блок категорий в левой панели на экранах задач и досок | Он нужен только на экране календаря, на экранах досок там идёт список досок |
| Подпись под названием задачи в календаре | В этих данных есть только название |
| Интервал времени у задачи, например «14:00 – 14:30» | У задачи только дедлайн |
| Вкладки «Мои» и «Отслеживаемые» | Фильтр из раздела 6.6, наблюдателей в модели нет |
| Панель статистики и переключатель календаря на экране задач | В MVP нет, календарь живёт в своём разделе |
| Скрепка с числом вложений | Вложений в MVP нет |
| Фильтры «Статус» и «Сортировка» на Kanban | Статус задаёт колонка, а порядок задаёт перетаскивание |
| Звёздочка у доски и поиск по доске | В MVP нет |
| Цветные точки у колонок | Поля цвета у колонки нет: завершающая зелёная, остальные нейтральные |
| Карточки Kanban без приоритета и числа комментариев | Оба показателя нужны, см. раздел 6.10 |

## 4. Каркас и навигация

| Ширина | Каркас |
|---|---|
| От 1200 px | Левая панель навигации, основная область, правая вспомогательная панель |
| От 768 до 1199 px | Навигация свёрнута в иконки, правая панель открывается по кнопке |
| До 768 px | Верхняя шапка, контент, нижняя навигация, плавающая кнопка «+» |

**Левая панель:** логотип, Календарь, Задачи, Доски. На экране календаря ниже идут категории с переключателями и слой «Задачи». На экранах досок там же идёт список моих досок. Внизу Настройки и профиль.

**Верхняя панель на компьютере:** поиск, колокольчик со счётчиком непрочитанных, профиль.

**Нижняя навигация на телефоне:** Календарь, Задачи, Доски, Настройки. Поиск и колокольчик находятся в шапке.

Отдельного раздела «Списки» нет: список — это один из видов доски.

## 6. Экраны подробно

### 6.1 Вход

Поля: логин и пароль. Кнопка «Войти». Регистрации и самостоятельного сброса пароля нет, вместо ссылки подпись «Забыли пароль? Обратитесь к администратору».

Сообщения: «Неверный логин или пароль», «Слишком много попыток. Повторите через N мин».

### 6.2 Смена пароля

Открывается сама при первом входе и после сброса пароля, пропустить нельзя. Поля: новый пароль и повтор. Минимум 8 символов.

### 6.3 Календарь

**Шапка:** стрелки периода, название периода, кнопка «Сегодня», переключатель Месяц, Неделя, День.

**Месяц.** Неделя начинается с понедельника. В ячейке дата и элементы, лишнее сворачивается в «+N». Многодневные события и события на весь день идут полосой. Сегодняшний и выбранный дни выделены.

**Неделя и день.** Сетка часов, сверху строка для событий на весь день и сроков задач. Пересекающиеся события стоят рядом. Текущее время отмечено линией. Клик по пустому месту открывает форму с этим временем.

**Элементы календаря:**

| Элемент | Как отличается |
|---|---|
| Событие | Цвет категории, название, время |
| Совместное событие | То же плюс аватары или значок участников |
| Повторяющееся событие | Значок повтора |
| Срок задачи | Значок чекбокса, приоритет. Не занимает блок времени |
| Выполненная задача | Зачёркнутая и приглушённая |

**Правая панель:** заголовок с выбранной датой, события дня, задачи дня с чекбоксами, кнопка «Новое событие».

**Телефон:** компактный месяц с точками под датами, ниже события и задачи выбранного дня, плавающая кнопка «+».

**Данные:** `CalendarItem[]`, `Category[]`.

**Действия:** листать период, выбрать день, открыть элемент, отметить задачу выполненной, создать событие, переключить категории и слой задач.

### 6.4 Просмотр события

Показывает название, дату и время экземпляра, правило повтора, место, описание, участников, личную категорию, личное напоминание и связанные задачи.

Действия: Изменить, Удалить, Выйти из события. Последняя кнопка видна, только если участников больше одного.

Подтверждение удаления зависит от ситуации:

| Ситуация | Текст |
|---|---|
| Совместное | «Событие удалится у всех участников» |
| Серия | «Будет удалена вся серия» |
| Совместная серия | «Вся серия удалится у всех участников» |

### 6.5 Форма события

Создание и редактирование. Ошибка сохранения не должна терять введённые данные.

| Поле | Тип | Правила |
|---|---|---|
| Название | Текст | Обязательно, до 200 символов |
| Весь день | Переключатель | Прячет время |
| Начало и конец | Дата и время | Конец позже начала. Для «весь день» только даты, конец не раньше начала |
| Участники | Выбор из пользователей | Сам пользователь уже в списке |
| Категория | Выбор | Личная, можно не выбирать |
| Повторение | Выбор | Нет, каждый день, каждую неделю, каждый месяц |
| Окончание серии | Выбор | Появляется при повторении: никогда, до даты, N раз |
| Напоминание | Выбор | Нет или значение из раздела 8 |
| Место | Текст | Необязательно |
| Описание | Многострочный текст | Необязательно |

**Занятость.** Когда выбраны участники и время, под полем участников показывается занятость каждого на выбранный день: дорожка с серыми блоками и отмеченным интервалом события. На телефоне вместо дорожки подойдёт текст «занято 15:00–16:00». При пересечении появляется предупреждение, но сохранить можно.

**Подсказки:**

- Месячная серия на 29, 30 или 31 число: «В месяцах без этого числа повтор пропускается».
- Редактирование серии: «Изменения применятся ко всей серии». Поле даты показывает начало серии.

**Переключатель «Личное, Общее, Приглашение» из старых макетов не нужен.** Его заменяют категория и поле участников.

В окне создания можно сделать переключатель Событие и Задача, как на референсе. При редактировании он не нужен.

### 6.6 Задачи

Общий список карточек со всех доступных досок.

Фильтр: Все, Личные, Общие. Переключатель «Назначенные мне».

Группы: Просрочено, Сегодня, На этой неделе, Позже, Без срока. Внизу сворачиваемая группа «Выполненные».

**Строка задачи:** чекбокс, название, приоритет, срок, название доски, метки, аватары исполнителей, прогресс чек-листа `2/5`. Просроченный срок выделен.

**Правая панель:** каталог досок с иконками и числом открытых задач, кнопка «Новая задача». На телефоне общие доски идут под задачами.

**Данные:** `TaskSummary[]`, `Board[]`.

**Действия:** быстро добавить задачу строкой, отметить выполненной, открыть, отфильтровать.

### 6.7 Форма задачи

| Поле | Тип | Правила |
|---|---|---|
| Название | Текст | Обязательно, до 200 символов |
| Доска | Выбор | По умолчанию личная. При смене форма предупреждает, что метки сбросятся, а исполнители, которых нет на новой доске, снимутся |
| Колонка | Выбор | Колонки выбранной доски |
| Описание | Многострочный текст | Необязательно |
| Приоритет | Выбор P1–P4 | По умолчанию P3 |
| Дата начала | Дата | Необязательно, не позже дедлайна |
| Дедлайн | Дата и необязательное время | Необязательно |
| Исполнители | Выбор из участников доски | Можно несколько, можно никого |
| Метки | Выбор из меток доски | Можно несколько, можно создать новую прямо здесь |
| Чек-лист | Список пунктов | Добавить, отметить, удалить, поменять порядок |
| Напоминание | Дата и время | Личное, быстрые варианты из раздела 8 |
| Связанное событие | Выбор или создание | Необязательно |

При редактировании у формы есть две вкладки. На компьютере их удобно поставить отдельной колонкой справа от полей.

- **Комментарии:** лента от старых к новым и поле ввода внизу. У своих комментариев есть «Изменить» и «Удалить», у изменённых пометка «изменено». Только простой текст.
- **История:** лента от новых к старым. Запись содержит аватар, имя, время и текст из раздела 8.

Для viewer форма открывается только для чтения: комментарии и история видны, написать нельзя.

**Данные:** `Task`, `BoardColumn[]`, `Label[]`, `TaskComment[]`, `TaskActivity[]`.

### 6.8 Доски

Каталог досок: иконка, название, число открытых задач, аватары участников для совместных. Разделы «Личные» и «Общие». Архивные скрыты за отдельным фильтром. Личная доска по умолчанию всегда первая.

Действия: открыть доску, создать доску.

**Данные:** `Board[]`.

### 6.9 Доска: шапка и виды

Шапка: иконка, название, участники, переключатель Список, Kanban, Календарь, кнопка «Новая задача», меню доски.

Под шапкой фильтры: исполнитель, метка, «Только мои». Они действуют в любом виде.

Для viewer действия недоступны, рядом с названием доски стоит пометка «Только чтение».

При первом открытии показывается вид по умолчанию, дальше запоминается последний выбранный.

### 6.10 Доска: Kanban

**Колонка:** заголовок, число карточек, меню колонки, карточки, внизу «Добавить задачу». Завершающая колонка визуально отличается, например лёгкой зелёной тонировкой. Справа от последней колонки кнопка «Колонка».

**Карточка:** метки, название, приоритет, срок, аватары исполнителей, прогресс чек-листа, число комментариев. У выполненной карточки значок галочки. Просроченный срок выделен.

**Телефон:** колонка занимает около 85% ширины, соседняя выглядывает. Колонки листаются свайпом с привязкой, внизу индикатор текущей колонки.

**Перетаскивание:**

| Состояние | Что показываем |
|---|---|
| Наведение | Карточка откликается, курсор захвата |
| Захват | Карточка приподнята, на её месте пустой контур |
| Цель | Линия вставки между карточками, подсветка колонки |
| Край экрана | Доска и колонка прокручиваются сами |
| Отмена | Клавиша Esc или отпускание вне колонки возвращает карточку на место |
| Ошибка | Карточка возвращается, внизу сообщение |

На телефоне перетаскивание начинается с долгого нажатия, чтобы не мешать прокрутке. Колонки перетаскиваются за заголовок.

У перетаскивания есть две замены:

- Меню карточки с пунктом «Переместить в…»: выбор колонки и места. На телефоне это основной запасной путь.
- Клавиатура: пробел берёт карточку, стрелки двигают её, пробел отпускает, Esc отменяет.

Если в колонке больше 100 карточек, внизу появляется «Показать ещё».

**Данные:** `Board`, `BoardColumn[]`, `TaskSummary[]` по каждой колонке, `Label[]`.

**Действия:** перетащить карточку или колонку, добавить карточку в колонку, открыть карточку, отфильтровать, управлять колонками.

### 6.11 Доска: список

Карточки сгруппированы по колонкам и идут в порядке доски. Завершающие колонки свёрнуты. Порядок меняется перетаскиванием, на телефоне через долгое нажатие. Этот вид удобен для простых списков вроде покупок.

Действия: быстро добавить, отметить выполненной, изменить порядок, открыть задачу.

**Данные:** те же, что у Kanban.

### 6.12 Доска: календарь

Месячная сетка со всеми задачами доски со сроком, независимо от исполнителя. Событий здесь нет. На телефоне компактный месяц и список дня.

**Данные:** `TaskDeadline[]`.

### 6.13 Форма доски и участники

Поля: название, иконка, описание, вид по умолчанию. Список участников с ролями: Владелец, Редактор, Читатель. Добавить, сменить роль, убрать, выйти самому, архивировать доску.

Последнего владельца убрать нельзя. Личную доску по умолчанию нельзя архивировать.

### 6.14 Управление колонками

Меню колонки: Переименовать, Отметить как завершающую, Удалить.

**Удаление.** Если в колонке есть карточки, диалог просит выбрать колонку для их переноса. Последнюю завершающую и последнюю незавершающую колонки удалить нельзя, пункт отключён с пояснением.

**Смена признака завершения.** Диалог предупреждает: «Все N карточек будут отмечены выполненными» или «Отметка о выполнении будет снята у N карточек».

### 6.15 Метки доски

Список меток: цвет и название. Добавить, изменить, удалить. Удаление предупреждает, что метка исчезнет со всех карточек.

**Данные:** `Label[]`.

### 6.16 Уведомления

Список от новых к старым: значок вида, текст, кто сделал, когда, метка непрочитанного. Клик открывает объект и отмечает уведомление прочитанным. Сверху «Прочитать всё».

Если объект удалён, уведомление остаётся, но при клике показывает «Объект больше не существует».

**Данные:** `Notification[]`.

### 6.17 Настройки

| Раздел | Содержание |
|---|---|
| Профиль | Отображаемое имя, цвет аватара |
| Часовой пояс | Выбор зоны |
| Пароль | Текущий, новый, повтор |
| Категории | Список, название, цвет, добавить, удалить |
| Выход | Кнопка выхода |

### 6.18 Поиск

Поиск по названиям своих событий и доступных задач. Результаты разделены на «События» и «Задачи». Для серии показывается ближайший экземпляр.

## 8. Подписи и перечисления

**Приоритет:**

| Значение | Подпись |
|---|---|
| 1 | P1 Срочно |
| 2 | P2 Высокий |
| 3 | P3 Обычный |
| 4 | P4 Низкий |

**Роль на доске:** `owner` — Владелец, `editor` — Редактор, `viewer` — Читатель.

**Повторение:** Не повторять, Каждый день, Каждую неделю, Каждый месяц.

**Напоминание о событии:** Нет, В момент начала, За 5 минут, За 15 минут, За 30 минут, За 1 час, За 1 день.

**Быстрые варианты напоминания о задаче:** В день срока в 09:00, За день в 09:00, Выбрать дату и время.

**Категории по умолчанию:** Личное, Работа, Учёба.

**Вид доски:** Список, Kanban, Календарь.

**Колонки новой доски:** К выполнению, Готово.

**Уведомления:**

| `kind` | Текст | Когда |
|---|---|---|
| `event_added` | Новое совместное событие: {title} | Вас добавили в событие |
| `event_updated` | Изменилось событие: {title} | Изменились время, место или название |
| `event_deleted` | Событие удалено: {title} | Другой участник удалил событие |
| `event_removed` | Вас убрали из события: {title} | Другой участник убрал вас |
| `event_reminder` | Скоро начнётся: {title} | Сработало напоминание |
| `task_assigned` | Вам назначена задача: {title} | Вас назначили исполнителем |
| `task_updated` | Изменилась задача: {title} | Изменились название, срок или приоритет |
| `task_commented` | Новый комментарий: {title} | Комментарий к задаче, где вы исполнитель или уже комментировали |
| `task_due` | Сегодня срок: {title} | Наступил дедлайн |
| `task_reminder` | Напоминание о задаче: {title} | Сработало напоминание |
| `board_added` | Вас добавили на доску: {title} | Вас добавили на доску |

**История карточки.** Имя автора и время показываются отдельно, поэтому тексты безличные:

| `kind` | Текст |
|---|---|
| `created` | Карточка создана |
| `updated` | Изменено: название, срок |
| `moved` | Перенос: Бэклог → В работе |
| `completed` | Выполнено |
| `reopened` | Возвращено в работу |
| `assigned` | Назначен исполнитель: {имя} |
| `unassigned` | Снят исполнитель: {имя} |
| `labeled` | Добавлена метка: {название} |
| `unlabeled` | Убрана метка: {название} |
| `checklist_added` | Новый пункт: {текст} |
| `checklist_checked` | Пункт выполнен: {текст} |
| `checklist_unchecked` | Пункт снова открыт: {текст} |
| `checklist_removed` | Удалён пункт: {текст} |
| `event_linked` | Связано с событием: {название} |
| `event_unlinked` | Связь с событием убрана: {название} |

## 9. Состояния

На каждый экран с данными нужны эти состояния:

| Состояние | Что показываем |
|---|---|
| Загрузка | Скелетоны вместо контента, без блокировки каркаса |
| Пусто | Короткий текст и действие: «На этот день ничего нет», «Задач нет. Добавьте первую» |
| Пустая колонка | Область приёма карточки и подпись «Перетащите карточку сюда» |
| Перенос не удался | Карточка возвращается на место, внизу сообщение |
| Ошибка загрузки | Сообщение и кнопка «Повторить» |
| Ошибка сохранения | Форма остаётся открытой с данными, сверху сообщение |
| Ошибка в поле | Подпись под полем, фокус на первом неверном поле |
| Только чтение | Действия скрыты или отключены, рядом пояснение |
| Конфликт версий | Диалог, см. раздел 10 |
| Объект удалён | Сообщение и закрытие экрана. Форма предлагает создать объект заново с введёнными данными |
| Нет связи | Ненавязчивая полоса «Нет связи с сервером», данные на экране остаются |
| Сессия истекла | Переход на экран входа |

Каждому интерактивному элементу нужны состояния покоя, наведения, нажатия, фокуса и отключённое.

## 10. Живое обновление и конфликты

**Обновление.** Экран обновляется сам в течение 10 секунд после изменения другим пользователем. Анимация не обязательна. Открытая форма данными с сервера не перезаписывается. Во время перетаскивания обновления откладываются до отпускания карточки.

**Быстрые действия применяются сразу:** перетаскивание, отметка задачи, отметка пункта чек-листа, быстрое добавление. При ошибке действие откатывается и появляется уведомление внизу экрана.

**Перенос конфликтов не вызывает.** Если карточку одновременно перенесли двое, останется последнее положение, диалога нет.

**Конфликт.** Если пока форма была открыта, другой участник изменил объект, при сохранении появляется диалог:

- Текст: «Объект изменился, пока вы его редактировали». Ниже подпись «Последнее изменение: {имя}, {время}».
- Кнопка «Показать новую версию»: форма загружает свежие данные.
- Кнопка «Сохранить мои изменения»: сохраняет поверх.

Введённые данные не теряются ни при каком выборе, пока пользователь сам не откажется от них.

## 11. Время и даты

- Время показывается в часовом поясе из профиля, в 24-часовом формате.
- Даты на русском: «6 ноября», «Пт, 6 ноября», «Ноябрь 2026».
- Неделя начинается с понедельника.
- Событие на весь день не имеет времени и не конвертируется между часовыми поясами.
- Если задача без времени, срок выводится только датой.

## 12. Что не рисуем

- Вложения, упоминания и форматирование в комментариях.
- Вид таблицы на доске.
- Перетаскивание событий в календаре и сроков на календаре доски.
- Приглашения, статусы ответа, входящие.
- Настройки доступа к занятости.
- Правка и удаление одного экземпляра серии.
- Push, запрос разрешений браузера, установка PWA.
- Регистрация и самостоятельное восстановление пароля.
- Админ-панель и управление API-ключами: это CLI на сервере.
- Настройки уведомлений.

## 13. Общие компоненты

Стиль держится на общем наборе компонентов, поэтому они делаются первыми и используются на всех экранах: кнопки, поля, выборы, аватары, диалоги, элементы календаря, строка задачи, карточка и колонка Kanban, метка.

Если для сложного экрана всё же понадобится отдельный макет, он кладётся в [design/](../design/README.md).
