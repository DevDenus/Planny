# API

Закрытый REST API, общий для сайта и локальных клиентов. Это рабочая схема: для реализованных маршрутов контрактом является сгенерированный `backend/openapi.json`, остальные описаны здесь. Типы объектов описаны в [frontend.md](frontend.md#7-модели-данных).

## 1. Общие правила

- Базовый путь `/api/v1`, формат JSON, идентификаторы UUID.
- Моменты времени в ISO 8601. Ответы всегда в UTC: `2026-11-06T16:00:00Z`. Даты без времени: `2026-11-06`.
- Периоды полуоткрытые: `from` входит, `to` не входит. Элемент попадает в выборку, если пересекает период. Период не длиннее 366 дней и лежит между 3 и 9996 годами, иначе `422`.
- `from` и `to` — моменты с часовым поясом. События на весь день и сроки без времени сравниваются по календарным дням в часовом поясе того, кто спрашивает.
- Все маршруты, кроме `/health`, требуют `Authorization: Bearer`.
- Права проверяются на каждом ресурсе, наличия действительного токена недостаточно.
- Списки с пагинацией принимают `limit` и `cursor` и возвращают `{items, next_cursor}`.
- Запись без доступа выглядит как отсутствующая: ответ `404`, а не `403`.

### Ошибки

```json
{
  "error": {
    "code": "version_conflict",
    "message": "Объект изменился",
    "details": {},
    "request_id": "01J..."
  }
}
```

| HTTP | `code` | Когда |
|---|---|---|
| 401 | `unauthorized` | Токена нет или он недействителен |
| 403 | `forbidden` | Объект виден, но действие запрещено, например viewer меняет карточку |
| 403 | `insufficient_scope` | Ключу не хватает scope |
| 403 | `password_change_required` | Нужно сменить одноразовый пароль |
| 404 | `not_found` | Объекта нет или нет доступа |
| 409 | `version_conflict` | `version` устарела, в `details.current` текущий объект |
| 409 | `id_conflict` | Клиентский UUID уже занят другим объектом |
| 409 | `invariant_violation` | Нарушено правило, например нельзя убрать последнего owner |
| 422 | `validation_error` | Ошибка в данных, в `details.fields` ошибки по полям |
| 422 | `range_too_large` | Период длиннее 366 дней |
| 429 | `rate_limited` | Слишком много попыток входа, в `details.retry_after` секунды ожидания |
| 500 | `internal_error` | Необработанная ошибка, подробности только в логах |

Эти коды отдаёт только BFF:

| HTTP | `code` | Когда |
|---|---|---|
| 403 | `csrf_failed` | Изменяющий запрос без верного `X-CSRF-Token` |
| 413 | `body_too_large` | Тело запроса больше 1 МБ |
| 415 | `unsupported_media_type` | `POST /bff/login` не в JSON |
| 502 | `upstream_unavailable` | Backend не отвечает |

Неверный логин, неверный пароль и заблокированный аккаунт дают один и тот же ответ `401 unauthorized`, чтобы по нему нельзя было узнать, какие логины существуют.

### Конкурентность и повторы

- `PATCH` на событие, задачу и доску обязан передать `version`. У задачи в `details` конфликта рядом с `current` есть `last_change`: кто и когда изменил её последним.
- Создание принимает необязательный `id`. Повтор с тем же `id` от того же пользователя возвращает существующий объект.
- Повторный `DELETE` отвечает `204`.

## 2. Scopes

Сессия сайта имеет все права пользователя. Ключ получает только перечисленные scopes.

| Scope | Что разрешает |
|---|---|
| `events:read` | Чтение событий и календаря |
| `events:write` | Создание, изменение и удаление событий |
| `availability:read` | Запрос занятости |
| `tasks:read` | Чтение досок и задач |
| `tasks:write` | Создание, изменение и удаление задач и досок |
| `notifications:read` | Чтение уведомлений и счётчиков |

Только для сессии: `/auth/*`, `PATCH /me`, управление категориями.

## 3. Маршруты

### Вход и профиль

| Метод и путь | Назначение |
|---|---|
| `POST /auth/login` | Вход, только с секретом BFF |
| `POST /auth/logout` | Закрыть текущую сессию |
| `POST /auth/change-password` | Сменить пароль: `{current_password, new_password}`, закрывает остальные сессии. При обязательной смене `current_password` не нужен |
| `GET /me` | Текущий пользователь |
| `PATCH /me` | Имя, часовой пояс, цвет |
| `GET /users` | Активные пользователи для выбора участников и исполнителей |
| `GET /health` | Проверка работоспособности, без авторизации |

Пока не сменён одноразовый пароль, доступны только `GET /me`, `POST /auth/logout` и `POST /auth/change-password`. Остальные маршруты отвечают `403 password_change_required`.

### Календарь

| Метод и путь | Назначение |
|---|---|
| `GET /calendar/items?from&to&layers=events,tasks&board_id&assignee&label_id` | Общий поток экземпляров событий и сроков задач. С `board_id` возвращает все задачи доски со сроком. `assignee` (`me` или id) и `label_id` сужают сроки задач так же, как в `GET /tasks` |
| `GET /events?from&to` | Экземпляры событий за период |
| `POST /events` | Создать событие |
| `GET /events/{id}` | Детали события |
| `PATCH /events/{id}` | Изменить событие или серию целиком |
| `DELETE /events/{id}` | Удалить событие у всех |
| `DELETE /events/{id}/participants/me` | Выйти из события |
| `GET /availability?user_ids&from&to&exclude_event_id` | Занятость пользователей |
| `GET /categories` | Свои категории |
| `POST /categories` | Создать категорию |
| `PATCH /categories/{id}` | Изменить категорию |
| `DELETE /categories/{id}` | Удалить категорию, у событий она сбрасывается |
| `GET /search?q` | Поиск по названиям своих событий и доступных задач |

Экземпляр в ответах `GET /events` и `GET /calendar/items` содержит `occurrence_start` и `is_recurring`. `start_at`, `end_at`, `start_date` и `end_date` у него свои, а в `GET /events/{id}` это первый экземпляр серии.

### Доски

| Метод и путь | Назначение |
|---|---|
| `GET /boards?archived` | Доступные доски |
| `POST /boards` | Создать доску с колонками по умолчанию |
| `GET /boards/{id}` | Детали доски |
| `PATCH /boards/{id}` | Название, описание, иконка, вид по умолчанию, архивация |
| `GET /boards/{id}/columns` | Колонки доски с числом карточек |
| `POST /boards/{id}/columns` | Создать колонку: `{name, is_done, after_id}` |
| `PATCH /boards/{id}/columns/{column_id}` | Название, признак завершения |
| `POST /boards/{id}/columns/{column_id}/move` | Изменить порядок: `{after_id}` |
| `DELETE /boards/{id}/columns/{column_id}?move_to` | Удалить колонку, перенеся карточки в `move_to` |
| `GET /boards/{id}/labels` | Метки доски |
| `POST /boards/{id}/labels` | Создать метку |
| `PATCH /boards/{id}/labels/{label_id}` | Изменить метку |
| `DELETE /boards/{id}/labels/{label_id}` | Удалить метку |
| `GET /boards/{id}/members` | Участники доски |
| `POST /boards/{id}/members` | Добавить участника |
| `PATCH /boards/{id}/members/{user_id}` | Изменить роль |
| `DELETE /boards/{id}/members/{user_id}` | Убрать участника или выйти самому |

### Задачи

| Метод и путь | Назначение |
|---|---|
| `GET /tasks` | Список с фильтрами, см. ниже |
| `POST /tasks` | Создать задачу. Без `board_id` попадает на личную доску. Необязательные `label_ids` и `checklist` со строками применяются в той же транзакции |
| `GET /tasks/{id}` | Детали задачи |
| `PATCH /tasks/{id}` | Изменить поля, включая `assignee_ids` и `label_ids` |
| `DELETE /tasks/{id}` | Мягко удалить |
| `POST /tasks/{id}/move` | Перенести: `{column_id, after_id}` |
| `POST /tasks/{id}/complete` | Завершить |
| `POST /tasks/{id}/reopen` | Вернуть в работу |
| `POST /tasks/{id}/checklist` | Добавить пункт чек-листа |
| `PATCH /tasks/{id}/checklist/{item_id}` | Изменить пункт или его порядок |
| `DELETE /tasks/{id}/checklist/{item_id}` | Удалить пункт |
| `POST /tasks/{id}/event-links` | Связать с событием: `{event_id}`. Отвечает `204` |
| `DELETE /tasks/{id}/event-links/{event_id}` | Удалить связь. Отвечает `204` |
| `GET /tasks/{id}/comments` | Комментарии, с пагинацией |
| `POST /tasks/{id}/comments` | Добавить комментарий |
| `PATCH /tasks/{id}/comments/{comment_id}` | Изменить свой комментарий |
| `DELETE /tasks/{id}/comments/{comment_id}` | Удалить свой комментарий, owner может удалить любой |
| `GET /tasks/{id}/activity` | История карточки от новых записей к старым, с пагинацией |

`POST /tasks` и `PATCH /tasks/{id}` принимают `reminder_at`: момент личного напоминания, `null` убирает его. Поле личное, в ответе оно своё у каждого. `PATCH` только с `reminder_at` не проверяет `version` и доступен всем, кто видит карточку, включая viewer. Момент в прошлом сохраняется, но не сработает.

Фильтры `GET /tasks`:

| Параметр | Значения |
|---|---|
| `board_id` | Одна доска |
| `column_id` | Одна колонка, этим запросом вид Kanban загружает карточки |
| `label_id` | Карточки с меткой |
| `scope` | `personal`, `shared` |
| `assignee` | `me` или UUID |
| `status` | `open`, `done`, `all`, по умолчанию `open` |
| `due_from`, `due_to` | Дедлайн в диапазоне дат |
| `overdue` | `true` — только просроченные |
| `no_due` | `true` — только без срока |
| `sort` | `due`, `position`, `priority`, `updated` |

### Уведомления и синхронизация

| Метод и путь | Назначение |
|---|---|
| `GET /notifications?unread_only` | Центр уведомлений |
| `POST /notifications/{id}/read` | Отметить прочитанным |
| `POST /notifications/read-all` | Отметить всё прочитанным |
| `GET /sync` | Счётчики версий и число непрочитанных |

## 4. Поведение отдельных маршрутов

### Создание события

Форма сохраняет всё одним запросом. Поля `category_id` и `reminder_minutes` личные: они относятся к тому, кто отправил запрос, и не защищаются `version`.

```json
{
  "id": "0195f3a2-7c41-7a11-9b3e-2f1f7e5c9a10",
  "title": "Ужин вдвоём",
  "all_day": false,
  "start_at": "2026-11-06T16:00:00Z",
  "end_at": "2026-11-06T18:00:00Z",
  "timezone": "Europe/Moscow",
  "participant_ids": ["0195f39f-2a10-7c55-8a21-1a2b3c4d5e6f"],
  "recurrence": { "freq": "monthly", "until": "2027-12-31", "count": null },
  "category_id": "0195f39f-2a10-7c55-8a21-9f8e7d6c5b4a",
  "reminder_minutes": [60]
}
```

- Создатель становится участником автоматически.
- `recurrence.until` — дата включительно в зоне события. `until` и `count` взаимоисключающие. Оба `null` означают бесконечную серию.
- `recurrence.count` от 1 до 1000. `until` не может быть раньше первого повтора: `422` с полем `recurrence`.
- Один повтор серии длится не дольше 366 дней: иначе `422` с полем `end_at` или `end_date`.
- `PATCH` принимает полный список `participant_ids`. Убрать можно любого, но хотя бы один участник должен остаться.
- `recurrence: null` в `PATCH` превращает серию в разовое событие. Остаётся первый экземпляр.
- `reminder_minutes` содержит до пяти значений от 0 до 43200.
- Если `PATCH` меняет только `category_id` и `reminder_minutes`, `version` не проверяется: своё ни с чем не конфликтует.
- Выход из события увеличивает `version`: форма, открытая раньше, иначе вернула бы вышедшего вместе со старым списком участников.
- `DELETE /events/{id}/participants/me` всегда отвечает `204`, в том числе постороннему: так нельзя проверить, существует ли событие. Если вышел последний участник, событие удаляется.

### Занятость

```json
{
  "items": [
    {
      "user_id": "0195f39f-2a10-7c55-8a21-1a2b3c4d5e6f",
      "busy": [
        { "start_at": "2026-11-05T12:00:00Z", "end_at": "2026-11-05T13:00:00Z" }
      ]
    }
  ]
}
```

- `user_ids` принимает значения через запятую или повторённым параметром, не больше 50. Неизвестный пользователь даёт `422`.
- Интервалы склеены и обрезаны по запрошенному периоду.
- `exclude_event_id` убирает из расчёта событие, которое сейчас редактируют, иначе оно пересекалось бы само с собой. Параметр работает, только если спрашивающий участвует в этом событии: иначе разница в ответе выдала бы время чужого события.

### Поиск

```json
{ "events": [ /* EventSummary */ ], "tasks": [ /* TaskSummary */ ] }
```

- Поиск без учёта регистра по подстроке в названии, `%` и `_` — обычные символы. До 20 результатов в каждом разделе.
- События идут от ближайшего к текущему моменту, у серии считается ближайший повтор в любую сторону. Открытые задачи идут раньше выполненных. Задачи архивных досок не находятся.

### Синхронизация

```json
{ "calendar": 41, "tasks": 87, "notifications": 12, "unread_notifications": 3 }
```

Значения сравниваются только на изменение, их абсолютная величина смысла не имеет.

### Перенос карточки

```json
{ "column_id": "0195f3a5-33cc-7def-8a23-5e4d3c2b1a0f", "after_id": "0195f3a4-11aa-7bcd-8e01-3c2b1a0f9e8d" }
```

- `after_id` — карточка, после которой встать. `null` означает начало колонки, а если поля нет, карточка встаёт в конец.
- Если `after_id` уже нет в колонке, карточка встаёт в конец. Ошибки в этом случае нет, потому что другой пользователь мог успеть её перенести.
- Перенос в колонку другой доски требует прав editor или owner на обеих досках. Метки сбрасываются, а исполнители, которых нет на новой доске, снимаются.
- `version` не передаётся. Ответ содержит обновлённую карточку. Перенос на другую доску, снявший метки или исполнителей, увеличивает `version`: форма, открытая раньше, иначе вернула бы их обратно.

Те же правила `after_id` действуют для колонок и пунктов чек-листа. При создании колонки `after_id` можно не передавать, тогда она встаёт в конец доски.

### Удаление колонки

`move_to` обязателен, если в колонке есть карточки, включая мягко удалённые, иначе ответ `422` с полем `move_to`. Удаление последней завершающей или незавершающей колонки отвечает `409 invariant_violation`, смена `is_done` у такой колонки тоже.

### Задачи в Kanban

Каждая колонка загружается отдельным запросом `GET /tasks?column_id=...&status=all&sort=position&limit=100`. Поэтому большая завершающая колонка не замедляет доску, а хвост догружается через `cursor`.

### История

```json
{
  "items": [
    {
      "id": 1842,
      "kind": "moved",
      "actor": { "id": "0195f39f-2a10-7c55-8a21-1a2b3c4d5e6f", "display_name": "Саша", "color": "teal" },
      "data": { "from_column": "Бэклог", "to_column": "В работе" },
      "created_at": "2026-11-06T11:30:00Z"
    }
  ],
  "next_cursor": null
}
```

## 5. BFF

Браузер не обращается к API напрямую. Он видит только эти маршруты:

| Путь | Назначение |
|---|---|
| `/` и статика | SPA |
| `POST /bff/login` | Вход, ставит cookie сессии и CSRF-токен |
| `POST /bff/logout` | Выход, закрывает сессию и очищает cookie |
| `/bff/api/v1/*` | Прокси на `/api/v1/*` по списку разрешённых префиксов |

Разрешены префиксы `me`, `users`, `events`, `calendar`, `availability`, `categories`, `search`, `boards`, `tasks`, `notifications`, `sync` и `auth/change-password`. Всё остальное получает `404`.

Изменяющие запросы требуют заголовок `X-CSRF-Token`. BFF добавляет `Authorization` и `X-Request-ID`, больше ничего в запросе не меняет.

## 6. CLI

Команды запускаются на сервере через `docker compose exec api planny ...`. Каждая пишет запись в `audit_log`.

| Команда | Назначение |
|---|---|
| `users create <login> --name <имя>` | Создать пользователя и вывести одноразовый пароль |
| `users list` | Список пользователей |
| `users block <login>` | Заблокировать, закрыть сессии, отозвать ключи |
| `users unblock <login>` | Разблокировать |
| `users reset-password <login>` | Выдать новый одноразовый пароль |
| `keys create --user <login> --name <имя> --scopes <список> [--expires <дата>]` | Выпустить ключ и один раз вывести секрет |
| `keys list [--user <login>]` | Список ключей без секретов |
| `keys revoke <id>` | Отозвать ключ |
