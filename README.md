# Planny

Закрытый планировщик для одной семьи на домашнем сервере: личные календари, совместные события, задачи и общие доски со списком, Kanban и календарём.

## Возможности

- **Календарь.** Личные события, совместные события с участниками, повторяющиеся серии, события на весь день, напоминания. Чужой календарь виден только как занятость, без деталей.
- **Задачи и доски.** Личная доска у каждого и общие доски с ролями owner, editor и viewer. Колонки-статусы, метки, исполнители, чек-листы, комментарии и история изменений. Три вида одной доски: список, Kanban с перетаскиванием мышью, касанием и с клавиатуры, календарь сроков.
- **Уведомления и синхронизация.** Уведомления о приглашениях, изменениях, комментариях и сроках. Открытая вкладка подхватывает чужие изменения в течение нескольких секунд без перезагрузки.
- **Интеграции.** Локальные сервисы ходят в тот же API по ключу со scopes. Ключи выпускает оператор.
- **Администрирование без веб-панели.** Регистрации нет. Пользователей, пароли и ключи ведёт оператор через CLI на сервере.

Подробно в [docs/features.md](docs/features.md).

## Как устроено

```
Интернет ─443─> Caddy ──> BFF + SPA ──> Backend API ──> PostgreSQL
Локальные сервисы ─LAN + ключ─────────>     ▲
Worker (напоминания, сроки, очистка) ───────┘
CLI оператора ─docker compose exec──────────┘
```

| Часть | Папка | Стек |
|---|---|---|
| Backend: API, worker, CLI | [backend/](backend/) | Python 3.14, FastAPI, SQLAlchemy, Alembic, Typer |
| BFF: cookie-сессии, CSRF, прокси, раздача SPA | [bff/](bff/) | Python 3.14, FastAPI, httpx |
| SPA | [web/](web/) | React 19, TypeScript, Vite, TanStack Query, FullCalendar, dnd-kit |
| Развёртывание и копии | [deploy/](deploy/) | Docker Compose, PostgreSQL 18, systemd-таймеры |

Вся бизнес-логика и проверки прав живут в backend. BFF логики не содержит, API наружу не опубликован. Подробно в [docs/architecture.md](docs/architecture.md).

## Запуск локально

Нужен Docker с Compose. Для тестов и линтеров ещё `uv`, `make` и Node 24 (версия в `web/.nvmrc`).

```bash
make up
```

При первом запуске команда создаёт `deploy/.env` со случайными секретами, собирает образы и поднимает стек. Сайт открывается на <http://localhost:8080>, API слушает только `127.0.0.1:8000`, база не опубликована.

Первого пользователя создаёт оператор. Команда выведет одноразовый пароль, при первом входе его нужно сменить:

```bash
docker compose --project-directory deploy -f deploy/compose.yaml -f deploy/compose.dev.yaml exec api planny users create sasha --name "Саша"
```

Остальные команды CLI описаны в [docs/api.md](docs/api.md#6-cli).

Для работы над интерфейсом удобнее `npm run dev` в папке `web/`: Vite открывается на <http://localhost:5173> и проксирует `/bff` в запущенный Compose.

## Команды разработки

| Команда | Что делает |
|---|---|
| `make up` / `make down` | Поднимает и останавливает стек разработки. Данные остаются в томе |
| `make logs` | Логи контейнеров |
| `make test` | Тесты backend, BFF и SPA. Для backend поднимает одноразовую PostgreSQL |
| `make e2e` | Сценарии в браузере на отдельном стеке со своей базой. Нужен `npx playwright install chromium` в `web/` |
| `make lint` | Форматирование, линтеры и проверка типов |
| `make format` | Исправляет форматирование |
| `make openapi` | Обновляет `backend/openapi.json` и клиент API в `web/src/api/`. Нужна после изменения маршрутов, иначе CI упадёт |
| `make migration name=...` | Создаёт миграцию Alembic по разнице между моделями и базой разработки. Файл нужно просмотреть |
| `make db-reset` | Пересоздаёт базу разработки из миграций, все данные в ней теряются |
| `make restore-check` | Копия и восстановление на отдельном стеке, включая повреждённые копии |
| `make trial-restore` | Пробное восстановление самой свежей копии во временный проект |
| `make release VERSION=x.y.z` | Комплект для сервера в `dist/` |

CI запускает линтеры, тесты, проверку снимка OpenAPI и сгенерированного клиента, а также `alembic check`. Сценарии в браузере в CI не входят, их запускают локально через `make e2e`.

## Сервер

Образы собираются на dev-машине и едут на сервер одним файлом, клон репозитория там не нужен:

```bash
make release VERSION=0.1.0
```

Команда собирает текущую рабочую копию в `dist/planny-0.1.0.tar`. Номер версии должен расти с каждым комплектом. Установка, обновление, откат, проверки и резервные копии описаны в [docs/deploy.md](docs/deploy.md) и [deploy/backup/README.md](deploy/backup/README.md).
